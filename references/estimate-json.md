# 估算结果 JSON 格式

估算结果是 Agent 与生成脚本之间的唯一交接物，放在项目目录内（不写进插件目录）。

## 结构

```json
{
  "项目名称": "咨询师预约平台",
  "项目类型": "新建",
  "输入": {"需求文档": "prd.md", "技术方案": "hld.md", "原型": "prototype/"},
  "任务": [
    {
      "需求": "用户可按分类、价格区间、最低评分与可预约时间组合筛选并排序咨询师",
      "需求出处": "PRD 3. 终端用户端需求 REQ-001 咨询师检索与筛选",
      "任务说明": "实现咨询师检索列表页：多条件筛选表单、排序切换、分页结果列表、空状态与热门推荐",
      "任务出处": "HLD 5.1 终端用户端页面 /user/search；原型 user/search.html",
      "子任务类型": "前端-页面-复杂查询列表页新建",
      "数量": 1,
      "修正场景": "",
      "修正系数": null,
      "人天分配": null,
      "备注": "导出入口在本页面实现，导出接口单独计一行"
    }
  ]
}
```

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `项目名称` | 否 | 报告标题使用 |
| `项目类型` | 否 | 如「新建」「调整」，只用于报告说明 |
| `输入` | 否 | 记录本次估算使用的输入路径，便于复核 |
| `任务` | 是 | 任务行数组，至少一行 |
| `任务[].需求` | 是 | 业务语言：要做的事（对应模板第一列） |
| `任务[].需求出处` | 否 | PRD 章节或需求编号；缺失时脚本告警 |
| `任务[].任务说明` | 否 | 技术语言：怎么实现（对应模板第二列） |
| `任务[].任务出处` | 否 | HLD 章节、接口路径或原型文件；缺失时脚本告警 |
| `任务[].子任务类型` | 是 | 基线里的子任务类型名称，含档位前缀（对应模板第三列） |
| `任务[].数量` | 否 | 同一子任务类型的实例数，默认 1 |
| `任务[].修正场景` | 否 | 基线「修正因子」里的场景名称 |
| `任务[].修正系数` | 否 | 数值，必须落在该场景区间内 |
| `任务[].人天分配` | 否 | `{"设计": x, "开发": y, "测试": z}`，给出后不再按换算系数派生 |
| `任务[].备注` | 否 | 写进模板备注列的自由说明 |

`子任务类型` 写完整名称（含 `简单` / `普通` / `复杂` 前缀），例如 `普通CRUD新建`；
也可以写成完整路径 `前端-页面-普通CRUD新建`，脚本都能查到同一行。
不写档位前缀时脚本会告警并给出同任务类型的三档候选。

评估文件第三列的「任务类型」由脚本按基线拼成 `任务大类-任务类型-子任务类型`，
例如 `前端-页面-普通CRUD新建`；基线未覆盖时原样写出 JSON 里填的值。

## 计算顺序

```text
基线开发人天 = 基线[子任务类型]
开发人天 = 基线开发人天 × 修正系数 × 数量
设计人天 = 开发人天 × 设计换算系数
测试人天 = 开发人天 × 测试换算系数
```

换算系数与修正因子都来自基线工作簿，JSON 里不写这些数值。

## 校验

- `子任务类型` 不在基线中：脚本告警「基线未覆盖」并列出候选，人天按 0 计；
- 缺少 `需求` 或 `子任务类型`：脚本直接报错退出，不产出文件；
- 缺少 `需求出处` 或 `任务出处`：脚本告警，两列语言分工无法复核；
- 修正系数超出场景区间：脚本告警，仍按给定值计算；
- 填写了 `修正系数` 但没有 `修正场景`：脚本告警并忽略该系数；
- 命中集成类任务类型：脚本忽略修正场景与修正系数并告警，人天只按基线档位与数量计算。
